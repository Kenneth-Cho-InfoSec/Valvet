# Valvet website: design record

## Direction

- Dealt direction: `type-only-statement`, seed `823890585`.
- Composition comes from the dealt sheet. Palette and type are fixed by the Valvet brand, so they were kept rather than redrawn.
- Idea: Valvet's own output is the exhibit. Diagnostics, generated C, typed frames, AST views, and install transcripts replace stock imagery.
- The one live thing: the tabbed code window. A visitor can switch between Valvet input, generated C, and diagnostics, and copy any panel. The same pattern repeats in the pipeline and examples.
- Voice: plain, technical, short. Claims come from the extracted site content; no customers, benchmarks, or platforms were invented.

## What the site contains

- `site/index.html`: hero, introduction, feature grid, interactive code, why Valvet, compiler pipeline, proof and test gates, standard library, install, docs, ecosystem, footer. The hero backdrop uses an inline leaping deer silhouette vector, drawn from the project's deer mark, with floating, breathing, tail, leg, and spark animations.
- `site/docs.html`: generated from `source-text/all-pages.txt`, 24 sections, 5 tables, search, scroll progress, and a section TOC.
- `site/examples.html`: generated from the same source, 14 runnable examples in Basics, Data, and Language groups, with filters.
- `site/privacy.html`: the privacy policy, generated by `build_pages.py` with the same header, footer, and prose styles as the docs. Its right-hand contents and summary panel close the frame on wide screens; both are hidden on small screens.
- `build_pages.py`: regenerates the docs, examples, and privacy pages, metadata, tables, and the no-JS fallback.
- Light lavender is the default theme. A dark theme persists in `localStorage` under `valvet-theme`. Code panels and the footer stay dark in both themes.

## Brand overrides of the house style

The client direction for this rebuild was explicit: lavender, lilac, violet, and white, with gradients, glassmorphism, glow, layered backgrounds, soft shadows, and premium motion. Those choices override the default house rules below. They are deliberate, not accidental.

| Rule | Site decision | Reason |
| --- | --- | --- |
| No gradients | Lavender gradients on the page field, cards, and primary actions | Brand direction |
| No glass | Translucent blurred cards on the landing, docs, and examples | Brand direction, used as a surface system rather than a single bar |
| No shadows or glow | Soft violet shadows and glow on primary actions and floating cards | Brand direction, depth cue for layered surfaces |
| No violet or indigo | Violet is the accent, ink, and field colour | Valvet brand |
| No gradient blobs or decorative shapes | The hero uses a leaping deer silhouette vector drawn from the project's mark | Brand asset, not filler. Its settings keep it behind the copy and out of the reading path |
| No outlined boxes | Large glass cards keep a light border; small controls use fill only | The border holds the glass surface together. Buttons, tabs, chips, filters, and inputs are borderless fills |
| Monospace only in code | Code, filenames, AST nodes, module names, formulas, and terminal output use the mono face | These are real identifiers or output. Prose uses Sora |
| Five type sizes maximum | 17 measured sizes, mostly inside code and interface fragments | Source code and terminal output keep their own scale. Prose uses a tighter set |
| Real pictures | Interface fragments and drawn diagrams, no stock photography or footage | A compiler's real material is its output. Stock photos of people at laptops would add fiction, not proof |
| No horizontal scroll | Documentation tables scroll inside a labeled, keyboard-focusable region at 390px | Tables keep their columns and meaning. Wrapping them would destroy row and column relationships |

### Landing (`inspect11`)

- FAIL: `gradient`, `shadow`, `button-fx`, `outlined-box` (9), `palette-purple`.
- WARN: `glass` (19), `size-count` (17), `no-real-pictures`, `no-footage`, `off-centre` (100px / 116px), `card-rows` at 390px.
- All FAILs are brand surfaces or the brand accent. The off-centre warning comes from card padding and the asymmetric hero, not from unequal page margins.
- The card-row warning at 390px is the feature list, which is a real list of capabilities, not a decorative card grid.

### Documentation (`docs9`)

- FAIL: `shadow` (primary button), `button-fx`, `outlined-box` (5), `palette-purple`.
- WARN: `card-rows` (8), `no-real-pictures`, `no-footage`, `still-page` (8 moving elements), `side-scroll` (one table at 390px).
- The repeated boxes are documentation sections and code examples. The table scroll is intentional and now has `tabindex="0"`, `role="region"`, and a table-specific label.
- Duplicate heading IDs were removed after the rebuild. Section IDs now live on the section element only.

### Examples (`examples5`)

- FAIL: `gradient` (14 cards), `shadow` (14 cards), `button-fx`.
- WARN: `glass` (14), `card-rows` (2), `no-real-pictures`, `no-footage`, `off-centre` (111px / 144px).
- The 14 cards are the 14 real examples. The off-centre value is the docs-style sidebar layout, not a broken frame.

### Privacy (`privacy8`)

- FAIL: `button-fx`, `palette-purple`, `few-pictures`.
- WARN: `no-footage`, `still-page` (12 moving elements).
- The page is a legal document, not a marketing page. It has no product imagery by design; the only picture is the logo. The inspector's four-picture floor would be met only by adding filler, so it is a documented exception.
- The right-hand contents and summary panel keep the page frame balanced. The summary panel is hidden at 980px and below, where the policy text uses the full width.
- Links use `--accent-strong` so body links meet 4.5:1 contrast on the lavender ground.

`lint.mjs` reports the same brand-driven patterns in source. It was not silenced with ignore comments because the overrides are global and documented here.

## Motion

- Scroll reveals animate from `opacity: 0.22` and `translateY(18px)` to the visible state. Content is visible by default if the observer never runs.
- Section headings and ledes are not hidden before reveal.
- Code typing, counters (680ms), pipeline tabs, particles, parallax float cards, hover states, and the back-to-top control are all present.
- The hero deer floats and breathes, its tail sways, its legs shift subtly, and the antler sparks and dust motes pulse. `prefers-reduced-motion` stops all of it while keeping the deer visible.
- `prefers-reduced-motion` disables particles, typing travel, parallax, smooth scrolling, and reveal travel while keeping content visible.
- The no-JS fallback hides dead controls and shows every code panel, stage panel, module, docs section, and example.

## Accessibility

- Skip link, visible focus rings, and real buttons and links.
- Mobile menu focuses the first link on open and returns focus to the toggle on close.
- Docs TOC and examples TOC are disclosure controls with a visible chevron. They open on desktop and stay collapsed on small screens.
- The privacy contents list is a navigation landmark. It is hidden on small screens, where the policy is short enough to scroll.
- Documentation tables are labeled scroll regions with keyboard access.
- Theme toggle, filters, code tabs, and copy controls expose state through ARIA and visible text.
- Metadata: canonical URLs, OG and Twitter cards, JSON-LD on the landing page, plus `robots.txt` and `sitemap.xml`.

## Content and version note

The site content uses version `0.3.0` from the extracted source. The compiler and port work is at `0.4.0`. The website should only be updated to `0.4.0` after the release content is verified; this rebuild did not invent release notes.

## Not claimed

- No real photographs or video were added. The inspector's picture and footage warnings stand, on purpose.
- The remaining inspector FAILs are brand-driven and were not "fixed" by removing the lavender, glass, glow, or violet direction.
- Visual checks were run in Chromium through the inspector. Firefox was opened manually for a smoke look, but the measured gate is the Chromium run.
