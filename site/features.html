Valvet is a small compiled language for numeric analyses and data programs. Version 0.5.0 extends its existing frame and modeling stack with typed data pipelines.

Typed data with explicit missing values

Use TypedFrame when a schema matters or keep using DynamicFrame for the existing text-column workflows. Typed columns cover numeric, boolean, string, and factor values; missing cells remain explicit as Missing<T>.

  • Read strict or lenient typed CSV and typed JSON, with schema inference for supported inputs.
  • Describe typed columns with summaries and convert between typed and dynamic frames.
  • Use typed statistics while keeping missing counts separate from non-missing data.

For the full API boundary and examples, see typed-frame documentation.

Group, join, and reshape data

Group on multiple keys while preserving first-seen order. Aggregations include counts, missing counts, sum, mean, minimum, maximum, variance, and standard deviation. Typed inner, left, right, and full joins produce an audit; missing keys do not match by default.

Grouped window operations include lag, lead, row number, cumulative sum, and rank while retaining the input row order. Existing dynamic-frame paths continue to support SQL subsets, frame verbs, validation, plotting, and the modeling library.

See the runnable examples for the existing frame and SQL usage.

Read selected binary formats and build lazy plans

The 0.5.0 release adds bounded Parquet and Arrow readers, plus writers for one-row-group Parquet and one-record-batch Arrow files. The readers support documented primitive subsets; unsupported nested or dictionary-encoded Parquet and compressed Arrow inputs return errors.

Flat lazy plans can select, filter, summarise, join a materialized frame, arrange, limit, collect, optimize, and explain. Lazy-to-lazy joins are deferred.

Analysis and the compiler

Earlier releases add units of measure, deterministic parallel summation, automatic differentiation, statistics, regression models, hypothesis tests, SQL over dynamic frames, and static plotting. These features live alongside the typed-frame layer; the newer data path does not replace them.

Valvet’s Rust frontend parses, type-checks, and borrow-checks a program before lowering it to C11. A system C compiler produces the native executable. The program’s prelude is emitted into the translation unit; there is no Valvet runtime library or garbage collector.

Build from source with stable Rust and a C compiler. VALVET_CC can select the compiler when needed. The beginner tutorial validates the first build and run.

Current limits

  • Single C translation unit and local machine target.
  • No closures, traits, general user-defined generics, FFI, or macros.
  • Parquet and Arrow support is intentionally narrow; see the format section above.
  • Lazy-to-lazy joins are not yet implemented.
  • --hermetic is a compile-time policy gate; it is not an operating-system sandbox.

Check the comparison page to see when another ecosystem may suit your workflow better. Read the repository README and release notes for current installation details.
